# 声音、组片与验收

## 统一声音

先按段试音，再细分到全片绝对时码，记录文本、声音、语速、实际时长和文件。让人名、班级等读法明确，例如“一零四班”。超时先改文案，必要的小幅语速调整需试听，不能仅以数值塞入时窗为准。

本项目 `make_voice.py` 使用 macOS `say -v Tingting`，输出 AIFF，FFmpeg 转48kHz双声道 WAV，逐句 loudnorm 后以 adelay 放到108秒底轨，amix 和 alimiter 合成统一旁白。这是可用本地路径，不代表用户指定了所有未来项目的配音服务。复用前检查 `say -v '?'`、系统声音、语言与授权；平台不支持时说明缺项并按用户要求选择声音来源。

按每镜 start 从全片旁白切取，可以让跨镜句子自然连续。环境音独立铺底，铃声与提醒点按时码加入。历史渲染用低音量粉红噪声作室内底噪、正弦提示音，部分片段混入模型原声；不能将它描述为真实现场录音或完整配乐。模型音轨可能夹带对白/音乐，需完整试听后决定保留范围。

已混入旁白的分镜再次组片时保留源音轨，不再添加统一旁白；静音画面方案则关闭源音，只在总时间线加旁白一次。音乐按使用需求和来源安排，避免遮挡提示与吐字。

## 已有成片的配音替换

- 先核对最新用户回复、实际WAV/成片、工程及任务记录。用户已接受试音并要求替换全片时，继续生成与导出，同步过期的“等待试音确认”字段。服务在线或工程就绪不表示整片配音已经完成；中断后先检查已有任务和文件，避免重复提交。
- 固定用户接受的 provider、voice、preset、speed；“少年感”“儿童感”是试听偏好，不能据此宣称原生儿童参考音色。不要因为软件默认服务变更而替换已确认的声音。声音年龄、自然度与读音需要听审。
- 分离显示文案和配音输入稿。必要时为多音字使用同音字或服务支持的发音标记，字幕始终保留正确汉字。先试读人名、称量等歧义词，保留规则、输入、音频和任务ID；文本替换成功不证明实际读音正确。
- 将每句实测时长放进当前镜头的绝对时窗；同镜多句合计必须计算句间停顿。换声音后不能沿用旧配音时长或直接套旧字幕时码。先清理首尾多余静音、适度缩短长停顿，保留呼吸和词尾余量；仍超窗再调整文案或小幅语速并复核。不要截词、无说明改画面速度或硬塞整句。

## 有限时长混音与故障恢复

混音前明确总秒数、采样率、声道和样本数。FFmpeg使用 `apad` 等可产生无限音频的滤镜时，输出端同时设 `-t TOTAL` 或明确样本上限。观察输出时长和体积；48kHz、16位、双声道PCM约192000字节/秒，约一分钟应为十余MB，持续增长至GB说明异常，应停止本轮对应进程后排查。滤镜链时长约束与输出端上限都不能代替实际音频验收。

本案例曾出现混音文件异常增长，增加输出上限后又得到约0.08秒的静音文件；未确认根因，不能把某个FFmpeg滤镜认定为已证实的原因。后续改用按样本定位的PCM混音恢复。不能只因进程退出码0就开始交付。

简单旁白可用有界PCM混音：统一格式→逐句测RMS/峰值并限制增益→按 `round(start × sample_rate)` 放入固定长度底轨→检查重叠、越界和削顶→写WAV。仅在已检测的静音区裁剪停顿，保留原始WAV和处理区间；使用PCM不意味着用户授权更换配音服务。RMS dBFS与LUFS是不同指标，不能混称“响度已达标”；目标值按项目确定。

旁白混音通过检查后再挂载与导出：

- WAV实测总时长/样本数正确；每个句子时窗非静音，句尾未越界，峰值无削顶。
- 从最终MP4解码音频，再核对每句时窗的音量和完整性；只有音轨存在、文件有声或全片平均非零都不足以证明9句全部导出。
- 新SRT与烧录字幕均使用新配音时码；抽查正确汉字、显示边界及遮挡。复用的字幕图层需确认文案与本版一致。
- 工程已挂新旁白，保存新快照；render清单、输出名、任务日志、处理参数与验证报告均能定位本版。仅重试当前失败步骤，不默认运行可能删除成功输出的历史脚本。

技术验收、字幕抽查、完整观看试听和用户接受分别记录。没有实际听审能力时明示缺项，不把静音检测或发音输入稿当成听审结论。

## 精确文字与衔接

Pillow、Swift AppKit 或 FFmpeg 均可本地排字；中文字体先检查可用性，不把本机字体路径当通用依赖。电视/屏幕文字按四角透视贴合，不交给生成模型重写。人物遮挡文字区域时需要遮罩或重新构图，不能用矩形覆盖人物动作。

回顾、儿歌、片尾的底层使用已验收交付片段实际末帧。历史108秒案例：S22复用S21并按1.2秒轮播五张回顾图；S25—S28复用S24，每镜4秒、两句各高亮2秒；S30复用S29定格3秒。不要倒放/往返循环人物来填长静态段。

## CutPot 组片

运行前检查项目中的 `docs/cutpot-cli.md` 和当前 `--help`。可以直接调用 `node /Users/qiubin/Documents/cutpot/bin/cutpot-cli.js`，不必修改全局命令。Node22+、ffmpeg、ffprobe、libx264 是本地依赖。

```sh
cutpot-cli doctor
cutpot-cli render /absolute/film.json -o /absolute/output/film.mp4 --json
```

render 清单与制作清单不同；见 assets 中两个模板。render/compose 会导入素材但保留工作台当前时间线。默认拒绝覆盖，不默认加 --force。成功导出 MP4、SRT、project.json、report.json。字幕独立 SRT，预览覆盖层不等于烧录；若要求烧录，另做并核对字体和遮挡。

CutPot 当前只硬切、固定音量混音，旁白从0开始、音乐循环并尾部淡出；复杂叠层、逐句高亮、电视透视、分段音乐压低在外部先合成。视频不足会报错，不自动慢放或补帧。浏览器与 CLI 不并行改工程，必要时先备份快照；快照依赖本机素材库。

## 技术与内容分别验收

使用随 Skill 的 verify_media.py 检查清单和实际视频。缺文件必须列为失败，不能跳过后声称全镜通过；已有报告只有当输入/输出版本未变才可复用。

技术检查至少含尺寸、帧率、帧数、音轨要求和完整解码，混音另查响度、峰值、非全零、句子边界和截尾。目标25fps时镜头帧数等于 duration×25；108秒为2700帧。全片再次检查总长、接缝、末帧、音画同步和字幕。

内容检查需完整观看并在关键位置逐帧：角色身份、背景变化、动作完整性、空间因果、道具接触、文字准确、裁切后头脚、字幕遮挡。抽帧拼图仅用于筛查。分别记录技术结论、画面结论、试听结论及修复/替代说明，不自动将技术 passed 升格为创作验收。
