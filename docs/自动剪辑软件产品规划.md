# CutPot 自动剪辑软件产品规划

版本：v0.1 · 2026-10-19 · 产品规划，尚未实施

## 1. 产品定位与首版假设

将 AI 生成的零散镜头，按照脚本、分镜或旁白，自动编排为可修改、可导出的完整视频。

首版定位为个人创作者使用的本地桌面工具，先在 macOS 验证。以有明确脚本的教育短片、故事解说和知识视频为切入点，先验证 1—10 分钟项目，再以 30—60 分钟项目做长视频压力测试。时长范围是规划目标，尚未经过性能验证。

最重要的体验：导入素材 → 对应分镜 → 一键生成初剪 → 只修改有问题的镜头 → 导出。

首版接受已经生成的视频，不内置视频生成平台。后续通过统一接口接入生成服务，避免将项目格式绑定到某一家模型。

## 2. 三种组片方式

### A. 分镜驱动：首版主流程

用户已有镜头顺序、旁白和目标时长。导入镜头清单与视频，通过镜头编号自动对应；用户检查匹配后生成时间线。确定性最强，也适合当前项目。

例如分镜 03 需要 3 秒，而生成视频为 5 秒：用户或分析器选择有效区间，裁切至 3 秒。旁白不足时允许保留停顿；视频不足时标记缺口，交给用户选择补镜头、调整段落或使用已批准的静态镜头。

### B. 旁白驱动：第二阶段

先导入完整旁白和脚本，再按语句对齐时间，检索相符的素材铺入画面。以实际语音时间为基准，不仅按字数估算。需要语音识别／强制对齐和镜头语义分析。

### C. 素材驱动：后续探索

只有素材时，系统给出候选结构和说明，用户确认后组片。它适合氛围片和蒙太奇；剧情片仍需要用户提供叙事关系，不能承诺自动理解并修复全部故事连续性。

## 3. 完整使用流程

1. **新建项目**：选择画幅、分辨率、帧率、目标时长，以及“精确时长”或“随内容变化”。首版默认 16:9、1080p、25fps，可设置。
2. **导入素材**：批量导入视频、图片、旁白、音乐和字幕，支持文件夹；检查可解码性、时长、尺寸、帧率、音轨，生成缩略图与低清代理。
3. **建立镜头清单**：支持手动填写及 CSV／JSON 导入；记录章节、镜头编号、画面描述、旁白、目标时长和可选素材。已有 Markdown 脚本先提供辅助解析和人工确认，不静默认定时码正确。
4. **对应素材**：先按分镜编号和用户指定关系匹配，再按文件名提示；多个候选展示版本供选择。语义匹配进入第二阶段。
5. **生成初剪**：按镜头顺序、有效区间、锁定项及音频安排计算时间线，检查时长是否可实现，生成可播放预览。
6. **集中修正**：问题清单定位缺素材、时长不足、音频冲突和待确认的匹配；支持替换、裁切、拖动顺序、字幕修改、音量调整和撤销。
7. **导出交付**：生成 MP4、可选无字幕母版、SRT 字幕和项目文件；导出前显示时长、格式及尚未解决的问题。

## 4. 首版必须完成的功能

- **素材管理**：镜头编号、标签、候选版本、有效入出点、原声保留／静音；保留源文件，不覆盖原素材。
- **自动组片**：按已确认的分镜编排；裁切、硬切、可选叠化；图片定格；时长缺口提示。
- **简化时间线**：主视频轨、旁白轨、音乐／环境声轨、字幕／标题轨；首版仅支持有限的叠加类型，暂不做任意多视频轨编辑器。
- **人工修正**：镜头替换、入出点调整、顺序调整、锁定镜头／区间、撤销重做、自动保存和版本快照。
- **声音处理**：旁白优先、原声开关、音乐淡入淡出、按旁白区间压低音乐；响度处理可选，允许试听后修改。
- **字幕**：导入 SRT、手动编辑、样式和安全区；已有准确时码可直接使用。自动语音字幕进入第二阶段，避免首版依赖模型服务。
- **导出可靠性**：任务进度、取消、失败原因、重试与缓存复用；空间预检；完成后校验可播放性、音视频时长和输出格式。

首版不纳入：内置视频生成、多人协作、口型修复、人物外观修复、复杂特效、自动发布平台、所有专业剪辑工程格式的兼容。

## 5. 自动剪辑的决策规则

### 5.1 匹配和连续性

分镜编号／人工关联优先于语义相似度。人物、场景、时间、动作前后关系作为后续辅助分析字段；低置信度结果必须可见、可替换。AI 可以提示“校服可能变化”“运动方向可能跳变”，不能据此自动声称修复了连续性。

保留每次选择的依据：镜头编号匹配、用户指定、候选评分及使用区间。用户应能回答“为什么这里用了这个片段”。

### 5.2 时长与转场

- 实际旁白存在时，优先保证语句完整。精确时长模式下遇到冲突，提示调整脚本、替换素材或改变段落，而非偷偷截断旁白。
- 素材过长：优先裁切有效动作；自动选区在后续阶段提供，首版使用人工标记或全片段默认区间并提示检查。
- 素材过短：优先使用同一镜头的其他已批准素材；否则报告缺口。定格、重复和变速均需项目策略允许，默认不自动启用。
- 第一版允许人工设置轻微变速；对白／口型镜头默认禁用自动变速。不得无限拉伸以满足目标长度。
- 同轨叠化会产生重叠：成片总时长 = 各片段编排时长之和 − 转场重叠时长之和。精确时长项目优先硬切；启用叠化时重新核对旁白对齐和总长。
- 所有视频时码以整数帧或有理数存储，音频保留采样级时间；不能逐段累积浮点误差。

### 5.3 局部重剪

换一个镜头时保留已锁定的字幕、配音和其他镜头。先尝试保持原镜头时长；无法满足时展示对后续时间的影响，由用户选择保持时长或波纹调整。重新自动编排前生成版本快照。

## 6. 工作台布局

顶部：项目名称、自动保存状态、生成初剪、版本、导出。

左侧：分镜列表与素材库切换，显示镜头编号、候选版本和缺口。

中央：视频预览，支持原素材／成片切换和当前镜头循环播放。

右侧：当前镜头的有效区间、时长、原声音量、关联旁白、转场及匹配依据。

底部：可缩放时间线及问题清单。普通用户以分镜列表完成主要操作，精细修正时才使用时间线。

## 7. 技术方案建议

建议采用 Electron + React + TypeScript 构建桌面界面与本地任务调度，FFmpeg／ffprobe 负责媒体检查、代理、合成与编码，SQLite 保存素材索引和任务状态，版本化 JSON 保存可迁移的项目与时间线。具体依赖版本在实施时锁定。

这是围绕本地媒体和长任务体验的设计选择，尚未进行框架对比或性能基准测试。先验证裁切、预览和渲染的一致性，再投入完整编辑器。

核心模块及职责：

1. **媒体摄入**：解析、校验、哈希／指纹、缩略图、代理、源文件重定位。
2. **项目模型**：章节、分镜、素材版本、轨道、片段、字幕、版本快照。
3. **编排引擎**：执行确定性规则，生成时间线及缺口报告；未来 AI 仅输出受校验的编排建议。
4. **预览引擎**：原素材代理播放与局部合成预览；复杂转场／字幕使用渲染预览，最终输出以前后端共享的时间线为准。
5. **渲染调度**：按依赖关系构建任务，记录进度、错误和取消状态，缓存稳定章节结果。
6. **AI 适配层（后续）**：语义标签、语音对齐、候选排序、补镜头提示词；媒体上传范围和费用在任务执行前明确展示。

FFmpeg 官方文档提供 concat、xfade、字幕与响度相关滤镜，可作为渲染基础；实际安装包需检查所需编解码器、滤镜和字体是否齐全。参考：[FFmpeg Filters](https://www.ffmpeg.org/ffmpeg-filters.html)。

项目 JSON 是首版唯一编辑事实来源。后续可评估 OpenTimelineIO 作为剪辑信息交换层；它提供剪辑信息格式和 API，不能据此保证各剪辑软件完整还原字幕、效果或字体。参考：[OpenTimelineIO 官方仓库](https://github.com/AcademySoftwareFoundation/OpenTimelineIO)。

### 长视频必须提前考虑

- 使用代理和按需加载，避免一次性把全部源文件解码进内存。
- 按章节渲染、限制并发，降低任务失败后的重算量。章节边界避免跨段特效；有跨界转场时需要额外重叠区间和裁切规则。
- 缓存键包含素材指纹、入出点、变速、滤镜、字体、输出规格和渲染版本；只复用已完成并校验的结果。
- 各章节统一尺寸、帧率、编码参数、时间基和音频格式后再拼接，处理音频编码延迟与时间戳。
- 渲染中断后复用已完成章节；不承诺从任意失败帧继续。
- 外部素材被移动时提供重定位；项目默认引用文件，另提供“打包工程”复制全部依赖。

## 8. 数据结构边界

- **Project**：输出设置、模式、章节、素材引用、当前时间线、模型版本。
- **Shot**：稳定 ID、分镜编号、叙事顺序、画面要求、旁白、目标时长、锁定项。
- **Asset**：稳定 ID、路径／指纹、媒体参数、代理、标签和来源记录。
- **ShotCandidate**：分镜与素材的关联、候选版本、有效区间、人工批准状态。
- **TimelineClip**：轨道、素材引用、源入出点、目标起点、播放速率、音量、效果。
- **Caption / AudioCue**：正文、时间区间、样式／音量、与镜头或旁白的关联。
- **RenderJob**：时间线快照、任务依赖、缓存键、状态、错误及输出清单。

镜头和素材分离：同一素材可以服务多个镜头，一个镜头可以有多个生成版本；更换素材不应丢失镜头的叙事意图。

## 9. 当前项目的落地示例

首个验证项目采用 `storyboard/一分钟教育短片制作方案.md`。该文件已有 60 秒时码、18 张入选分镜、旁白、声音与最后 5 秒静止提问要求，适合作为确定性编排基线。

拟定流程：

1. 将现有方案整理为镜头清单，继续引用现有分镜编号；静态图与未来视频均归属对应镜头。
2. 每个镜头导入多个 AI 视频版本，例如 `shot_03_v01.mp4`、`shot_03_v02.mp4`；文件名只是辅助，最终使用稳定 ID 关联。
3. 设置 1920×1080、25fps、精确 1500 帧；先生成静态预演，后续逐个替换为动态视频。
4. 门口相遇、楼梯提醒等镜头保留人工确认；最后 125 帧锁定为静止问题画面且无旁白。
5. 沿用已批准的故事与素材约束；缺少视频时保留明确标记，不自动混入其他项目的素材。
6. 验证导出有字幕版、无字幕版、SRT 和可再次编辑的项目。

这只是软件的验收案例，本次规划不生成或修改现有影片素材。

## 10. 开发顺序与完成标准

### M0：最小技术验证

完成导入、解析、按清单裁切拼接、单段旁白和 MP4 导出。使用静态图及已准备的测试视频验证混合尺寸、缺音轨和变帧率输入。先解决媒体链路，暂不接入 AI。

完成标准：能够从明确清单重复生成同一剪辑结果，错误可定位到具体素材与步骤。

### M1：可用首版

完成素材候选、分镜编辑、初剪、简化时间线、字幕／音乐、镜头替换、保存恢复和完整导出。用当前 60 秒案例验证全部工作流。

完成标准：1500 帧精确输出；最后 125 帧无旁白；预览与输出的镜头顺序、文字和切点一致；替换单镜头保留已锁定内容。

### M2：长视频可靠性

完成代理、缓存、章节渲染、失败重试和工程打包。测试 30 分钟／约 300 个片段的项目，并扩展至 60 分钟；这些是测试用例规模，不是已有能力。

完成标准：导出全片可解码，章节边界无新增黑帧、音频缺口或重复；累计时长无可见漂移；取消与重启后复用已完成章节；记录测试硬件、耗时、峰值内存和输出大小后确定支持范围。

### M3：智能辅助

加入旁白对齐、语义检索、质量提示和缺镜头清单；再评估生成服务连接。自动分析必须能降级为人工指定，且不能破坏已锁定的编排。

完成标准：使用人工标注案例检查候选命中率与误报；用户能理解建议、拒绝建议并恢复原版本。先建立基线再设定准确率目标。

排期需要根据开发人数、目标平台及样片实测估算，当前不承诺周数。

## 11. 后续需要确认的产品选择

当前先按以下默认值推进方案：本地桌面、macOS 首发、有脚本的教育／解说类视频、人工导入已生成素材、先实现确定性组片。

若主要目标是人物对白短剧，需要提高原声、口型与动作连续性的优先级；若主要目标是一小时以上批量生产，需要更早投入队列、性能和存储管理。两者都会显著改变首版范围。

下一项可执行工作：把当前 60 秒脚本转换为标准镜头清单及项目 JSON 样例，作为界面原型和最小渲染验证的共同输入。
