# CutPot 0.9 视频创作流水线

同一项目贯穿三个独立页面：`/storyboard` 分镜图创作、`/videos` 首尾帧视频、`/editor` 剪辑导出。根路径进入分镜图页面。原剪辑、配音、字幕和导出功能继续保留。

## 快速体验

运行 `./start.sh`，打开 http://127.0.0.1:4317。初次使用默认模拟模式，不调用外部生成服务。空项目可载入乐乐示例，也可输入脚本或批量导入自己的分镜图。脚本按段落和句子拆分，完整保留原文；目前不调用语言模型。如果句子数量不足，不编造额外故事内容。

1. 分镜图：添加共用主体参考图，输入脚本、统一风格与目标分镜数，拆分后逐镜编辑。生成、导入图片或选用历史候选，右侧预览随选择变化。
2. 首尾帧视频：有序 N 张分镜组成 N−1 个片段。每段可调整动作提示词与 1 至 10 秒时长。图片导航、片段导航、列表和检查面板联动。支持逐段生成和批量排队。
3. 检查：播放单段或连续播放已完成片段，检查首尾贴合和镜头衔接，并标记通过或返工。PSNR 来自 FFmpeg 对视频实际首尾帧与参考图归一化到 320×180 后的像素比较，单位 dB。23 和 15 是界面复查阈值，不代表美术质量或角色一致性已经通过。
4. 送入剪辑：全部片段有选用视频且没有上游过期或明确返工项后，送入 CutPot。尚未人工检查或包含模拟素材时，交接窗口明确提示。保留其他剪辑内容，已关联片段更新版本；重复交接不会添加重复镜头。锁定镜头不允许静默替换。剪辑页可继续配音、字幕和 FFmpeg 导出。

模拟图片是本地几何测试图，模拟视频是首尾图片的交叉淡化，只用于验证操作链路。它们会明确标记为模拟素材，不能用作真实视频生成的首尾参考图。

## 真实生成服务

在“生成设置”明确选择“真实生成”，再点击生成才提交任务。图片通过 `dreamina text2image/image2image`，参考图、提示词、画幅、分辨率和候选数量作为独立参数传入。模型遵循 CLI 当前默认，不固定截图中的模型名。

视频生成路径可在工作区右上统计栏或生成设置中切换：

- **AutoDL · 视频**（默认）：`autodl-cli job submit --modality video --play first_last_frame --image ... --end-image ...`，24 fps，横屏默认 768×432，竖屏 432×768，方形 768×768
- **即梦 CLI · 视频**：`dreamina frames2video --first ... --last ...`，默认 720p；时长须 4–15 秒

缺任一帧即拒绝，不降级模式。实际产物元数据由 FFprobe 确定。任务会记录所用路径，中断后继续查询仍走原 CLI。

复用两个 CLI 原有的登录、隧道、服务及预算配置，不复制密钥，不自动登录、开机、重建配置或擅自改走另一路径。可通过环境变量 `CUTPOT_DREAMINA_BIN` 和 `CUTPOT_AUTODL_BIN` 指定可执行文件路径，不支持任意 shell 命令。AutoDL 返回 demo/mock 时不标记为真实产物。

本轮开发只核对 CLI 帮助和接口，并使用本地模拟、真实 FFmpeg 及测试服务验证；没有提交付费图片或 GPU 视频任务。真实服务的账号、余额、连接及生成效果仍以实际运行结果为准。

## 状态、版本与恢复

- 创作状态按剪辑项目 ID 独立保存到 `.cutpot/pipeline.json`，旧项目记录保留。编辑项目名称在三页共享。多个窗口通过 revision 防止覆盖；冲突后刷新并重试，当前页的未保存输入保留。
- 任务输入、服务编号、产物与检查数据保存在 `.cutpot/generation/<任务ID>/` 和流水线记录中。每项生成前保存输入快照，队列串行提交，切换选中项不影响后台任务。
- 重生成添加版本，既有版本保留。任务返回时，若用户已经手动选了其他版本，不自动覆盖该选择。
- 上游图片或视频提示词、时长变化后，相应视频显示待更新。保留旧片、旧首尾帧引用与任务记录；选回原首尾图和参数可继续使用对应版本。
- 重新拆分或调整图片顺序前保存分镜历史，可从页面恢复。重新拆分不会改动已有剪辑工程。
- 停止排队仅停止尚未提交的任务，已提交任务继续运行。服务重启后，已知外部任务编号显示“待查询”，点击“继续查询”恢复跟踪和下载，不重新提交。提交阶段异常而没有返回编号时，须先核对 CLI 的服务任务列表，避免重复计费。
- 多候选与批量任务消耗以服务实际计费为准，不无限重试。远端查询或下载中断保留编号，服务失败显示具体原因。启动或关闭 CutPot 都不等于关闭 AutoDL GPU 实例。

## 验证与维护

运行 `./verify.sh`。测试需要 Node.js 22+、FFmpeg、FFprobe、Python 3 与 Pillow；字幕 Python 可通过 `CUTPOT_SUBTITLE_PYTHON` 指定。macOS 系统配音集成测试需要可用系统声音。

主要文件：`src/pipeline.js` 管理持久化、依赖、队列与交接，`src/generation.js` 封装 CLI 和 PSNR，`public/pipeline.*` 提供两个创作页面。`test/pipeline.test.js` 验证整个本地媒体链路、过期传播、冲突、重复交接和服务重启。
